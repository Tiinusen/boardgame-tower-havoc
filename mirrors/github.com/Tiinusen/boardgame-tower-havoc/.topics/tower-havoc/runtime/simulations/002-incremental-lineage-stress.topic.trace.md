# Incremental Tower Havoc Match-Lineage Stress

This topic extends the synthetic runtime work without rewriting the earlier eight-scenario corpus. Its first scenario is generated by a small deterministic simulation harness that materializes each artifact immediately as setup, turns, intents, random requests, runtime observations, resolutions, and states occur.

## Current Read

The important test is lineage rather than aggregate statistics. At no point does the harness first compute a finished match and then serialize a retrospective tree. Parent artifacts must already exist and verify before a child is emitted, random requests are written before their runtime/result artifacts, and every accepted transition is followed immediately by its state checkpoint.

## Design Direction

Keep the generated directory and filename structure aligned with the existing simulation examples: scenario-local `001-ruleset`, `002-match`, `setup/`, `turns/turn-NNN/`, and `terminal/`. Directory-local filename lineage continues to mirror local Parent placement while semantic Parent remains authoritative inside each artifact.

The harness is intentionally small and deterministic so Discord, GitHub Issue, CLI, or other runtimes can later use the same artifact vocabulary without Tower Havoc leaking into generic presentation/runtime domains.
